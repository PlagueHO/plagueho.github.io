## Layout

```text
repo-root/
├── .github/
│   ├── workflows/         # CI/CD pipelines
│   └── copilot-instructions.md
├── src/
│   ├── _config/           # Eleventy config modules (events, filters, plugins, shortcodes, utils)
│   ├── _data/             # Site metadata, navigation, design tokens
│   ├── _includes/         # Partials, WebC components, generated CSS/JS includes
│   ├── _layouts/          # Nunjucks page layouts
│   ├── assets/            # Source CSS, JS, images, fonts, icons, SVG, banners
│   ├── common/            # Feeds, sitemap, robots, utility pages
│   ├── pages/             # Top-level site pages
│   ├── posts/             # Blog content — src/posts/YYYY/MM/slug.md
│   └── projects/          # Project pages — src/projects/project-slug/slug.md
├── dist/                  # Generated output (do not edit)
├── eleventy.config.js     # Wires src/_config modules into Eleventy
├── tailwind.config.js
└── package.json
```

## Adding or Changing Content — Checklist

1. Place posts in `src/posts/YYYY/MM/YYYY-MM-DD-slug.md`; projects in `src/projects/project-slug/`.
2. Include required frontmatter fields: `title`, `date` (posts), `tags` (include `posts` to join the feed).
3. Use `isArchived: true` to retire a post — **do not remove the `posts` tag** to hide it.
4. Reference images as `/assets/images/…` so Eleventy Image optimises them.
5. Run `npm run build` and confirm it exits cleanly before committing.

## Modifying Build or Eleventy Behaviour — Checklist

1. Implement changes in the relevant `src/_config` module (not inline in `eleventy.config.js`).
2. **If adding a CSS entry point** — place it under `src/assets/css/`; the css-config plugin handles routing.
3. **If adding a JS entry point** — place it under `src/assets/scripts/`; the js-config plugin handles bundling.
4. Keep both `events/*.js` and `plugins/*.js` in sync when modifying asset pipelines.
5. Run `npm run build` and confirm it exits cleanly before committing.

## CI Pipeline

- **Build** (`gh-pages.yml`): runs `npm install` then `npm run build`; **fails on any build error**.
- **Deploy** (`gh-pages.yml`): runs only on push to `main` after a successful build job.
- **CodeQL** (`codeql.yml`): scans Actions YAML and JavaScript/TypeScript; **fails on detected vulnerabilities**.

## Conventions

| Concern | Rule |
|---|---|
| Config modularity | Logic lives in `src/_config` modules; `eleventy.config.js` only wires them. |
| Metadata | Update `src/_data/meta.js`, `personal.yaml`, or `navigation.js` — never hardcode in templates. |
| Content paths | `src/posts/YYYY/MM/` and `src/projects/project-slug/` — no exceptions. |
| Asset routing | Source assets under `src/assets/`; generated includes under `src/_includes/`. |
| `dist/` | Generated by the build pipeline — never edit directly. |
| Indentation | 2 spaces for JS, JSON, YAML, Nunjucks. |
| Quotes (JS) | Single quotes; template literals only when interpolating. |

## Permission Boundaries

**Allowed without asking:** edit `src/`, config files, workflow text; run any `npm run *` script locally.

**Ask first:** upgrading major dependencies, changing Node version constraints, deleting large content trees,
altering CI trigger semantics, pushing tags or release commits.

**When stuck:** stop and report the exact blocker; propose the smallest safe next step rather than a large speculative change.
